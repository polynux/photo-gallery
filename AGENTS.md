# AGENTS.md

Guidelines for AI coding agents working in this Laravel photo gallery application.

## Stack

Laravel 13, Filament 5, Livewire 3, Tailwind 4, Pest 3, PHP 8.5, Node 22, pnpm 10.
`composer.json` is the source of truth for versions — they are newer than typical
training data, so search version-specific docs before writing framework code.

The app serves photo galleries protected by 8-character access codes, generates
thumbnails via queued jobs, and offers public gallery viewing with ZIP downloads.
Galleries are grouped into universes; the admin panel is a Filament panel.

## Runtime: lerd

The dev environment is [lerd](https://github.com/laraveldark/lerd) (Podman-backed
Laravel Herd for Linux). Site config lives in `.lerd.yaml`, PHP/Node pins in
`.lerd.yaml` and `.php-version`.

- The `php`, `composer`, `node`, and `npm` on PATH are lerd shims: plain
  `php artisan ...`, `composer ...`, `npm ...` already run inside the site's
  container. Use `lerd php`, `lerd composer` etc. only to be explicit.
- Queue worker, task scheduler, and Vite are lerd-managed workers and already
  running. Do not start duplicates: no `php artisan serve`, no
  `php artisan queue:listen`, no `pnpm run dev`, and no `composer dev` — each
  would collide with its managed counterpart.
- Site: https://photo-gallery.test (HTTPS via mkcert). Outgoing mail lands in
  Mailpit; `lerd dashboard` opens the dashboard including the Mailpit UI.

## Commands

```bash
php artisan test --compact              # tests (filter: --filter=name, or pass a file path)
vendor/bin/pint --dirty --format agent  # format changed PHP — run before finalizing
composer lint                           # full lint (Duster); composer lint:fix to auto-fix
pnpm run build                          # production frontend assets
lerd status                             # environment health
lerd site:doctor                        # app-level health checks
lerd logs fpm|nginx|redis|mailpit       # container/service logs
```

Database: the site runs on sqlite (`database/database.sqlite`); tests run
against in-memory sqlite. Take a snapshot before risky migrations:
`lerd db:snapshot <name>` and restore with `lerd db:restore <name>`;
`lerd db:shell` opens an interactive shell.

## Conventions

PHP (Pint governs formatting — never hand-format):

- Curly braces on all control structures; explicit param and return types.
- Constructor property promotion; no empty `__construct()` unless private.
- Casts in a `casts()` method, not the `$casts` property.
- No inline comments unless the logic is genuinely complex; prefer PHPDoc with
  array-shape types for complex structures.

Laravel:

- Scaffold with `make:` commands, passing `--no-interaction` and required options.
- Models in `App\Models` (flat); factories with states for test data.
- Migrations are anonymous classes; foreign keys via
  `$table->foreignId('...')->constrained()->cascadeOnDelete()`.
- Column modifications must restate every previously defined attribute or it is lost.
- Thin controllers, form requests for validation, named routes with `route()`.
- Middleware, exceptions, and routing are registered in `bootstrap/app.php`;
  console configuration in `routes/console.php`.
- If API endpoints appear, use Eloquent API Resources.

Filament:

- Resources live in `app/Filament/Resources/<Resource>/Pages/`; use the
  Filament-specific `make:` commands (check `--help` for required options).
- Test via `livewire()` assertions and authenticate first.
- The admin panel is served at `/administrafion` — not `/admin`.

Views:

- Public views in `resources/views/public/`; components in `app/View/Components/`.

Testing (Pest):

- Create with `php artisan make:test --pest SomeName` (no suite directory in the name).
- Use model factories and their custom states; prefer feature tests.
- Do not delete or skip tests without approval.

## Architecture Notes

- **Disks**: `photo`, `thumbnails`, `private` (see `config/filesystems.php`).
- **Thumbnails**: generated by the `GeneratePhotoThumbnail` queue job as
  1920px JPEG at 80% quality.
- **Access codes**: 8-character random strings; password-protected galleries
  authenticate via the `authenticated_gallery_<id>` session flag.
- **Universes**: top-level groupings; `univers` Blade components render layout
  and preview pieces (`<x-univers :gallery="$gallery" />`).

## Guardrails

- New base directories, new dependencies, and documentation files require
  explicit approval first.
- Prefer Boost's `database-schema` before migrations, `database-query` over raw
  SQL, and `get-absolute-url` before sharing any URL with the user.

## Git Safety

Stage selectively: `git add` individual files or explicit paths, then review
`git status` and `git diff --cached` before committing. Bulk staging
(`git add .`, `git add -A`, `git add --all`, `git commit -a`/`-am`) sweeps in
secrets, binaries, and temp files — never use it. Never bypass hooks with
`--no-verify` or `--no-gpg-sign` unless explicitly requested.

Commit messages: conventional type + subject, details as a short body. Valid
types: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`.

```bash
git commit -m "feat: add new feature

- Detail 1
- Detail 2"
```

## Plane

Plane project: Pinaton Photos.

- **Commit before Done**: never move a Plane issue to Done while its code
  changes are uncommitted. First commit the work (staging files individually per
  Git Safety), then move the issue to Done with a closing comment referencing
  the commit hash.
- If an issue was marked Done before committing, move it back to In Progress
  with an explanatory comment, commit, then re-close it with the commit
  reference.
